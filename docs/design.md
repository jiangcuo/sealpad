# 印台 SealPad 设计文档

## 1. 目标与边界

印台是一个离线的 PDF 盖章工具，面向需要在合同、报价单、证明材料上盖章签字的个人和小团队。

- **完全离线**：不联网、不收集数据、不需要账号，文档和印章不离开本机。这是和在线签章平台最大的区别。
- **一套界面，两种形态**：网页版（GitHub Pages 静态部署）和桌面版（Tauri 2）共用同一个前端。
- **尺寸准确**：内部一律用毫米 / pt 计算，打印出来和实物印章一样大。
- **不做伪造工具**：首次启动和 README 明确提示只能使用有权使用的印章；示例印章标注「仅供体验」；后续的印章设计器会在 SVG 元数据里写明由本工具生成。

## 2. 架构

```
┌──────────────── apps/web（React + Fluent UI）────────────────┐
│ 界面：印章库 / 文档预览 / 属性面板 / 导入对话框              │
│ lib：pdf.js 预览、Canvas 图片解码编码、IndexedDB 印章库       │
│ platform：Platform 接口 ── web.ts（浏览器实现）               │
│                        └── tauri.ts（桌面实现，动态加载）      │
└───────────────┬──────────────────────────────────────────────┘
                │ 依赖
┌───────────────▼──────────────┐      ┌────────────────────────┐
│ packages/core（纯 TS）        │      │ apps/desktop（Tauri 2） │
│ 坐标变换、骑缝章切分、去白底、 │      │ Rust 外壳：对话框、文件 │
│ PDF 盖章导出（pdf-lib）       │      │ 读写；后续的原生能力    │
└──────────────────────────────┘      └────────────────────────┘
```

核心逻辑放在 `packages/core`，只依赖 pdf-lib，不碰 DOM 和 Canvas，在浏览器和 Node 里都能运行，单元测试直接在 Node 里跑。网页版和桌面版的差异全部收敛到 `apps/web/src/platform` 的 `Platform` 接口里，界面代码只依赖这个接口。

桌面版不单独写前端：Tauri 的 `frontendDist` 直接指向 `apps/web/dist`，运行时通过 `__TAURI_INTERNALS__` 判断环境，加载 `tauri.ts` 里的原生实现。

### 技术选型记录

| 决定 | 原因 |
| --- | --- |
| Tauri 2 而不是 Electron | 安装包小（通常 10 MB 以内，Electron 80 MB 以上）；网页版本来就要兼容 Safari / Firefox，Electron「统一 Chromium」的优势在这里打折；原生层用 Rust，适合后续的局域网服务、证书、UKey；Tauri 2 还支持移动端，以后需要时可以复用 |
| 核心逻辑用 TypeScript | 网页版必须在浏览器里完成全部处理，TS 核心可以同时服务两种形态 |
| pdf.js legacy 构建 | 带兼容补丁，国内常见的旧内核浏览器也能用 |
| pdf-lib 写入 | MIT 许可、纯 JS、成熟。局限见第 6 节 |
| Fluent UI v9 | 微软的设计体系，Windows 上观感接近原生 WinUI |
| 不支持 Win7 | Rust 1.78 起、WebView2 / Chromium 110 起都已不支持 |

## 3. 坐标系

这是最容易出错的地方，所以单独约定：

- **显示坐标**：页面按 `/Rotate` 顺时针旋转后呈现给用户的样子。原点在左上角，y 轴向下，单位毫米（界面）或 pt（计算）。界面上的所有位置、印章的 `Placement` 都用显示坐标保存。
- **PDF 用户空间**：原点在左下角，y 轴向上，可见区域由 CropBox 决定（不一定从 0 开始）。

`core/geometry.ts` 的 `visualToPdfMatrix(box, rotation)` 给出显示坐标到 PDF 用户空间的仿射变换，四种旋转分别是：

| /Rotate | x' | y' |
| --- | --- | --- |
| 0 | x0 + vx | y1 − vy |
| 90 | x0 + vy | y0 + vx |
| 180 | x1 − vx | y0 + vy |
| 270 | x1 − vy | y1 − vx |

导出时 `stampMatrix` 把图片的单位正方形依次映射到显示坐标（含印章自身的旋转）再到 PDF 用户空间，得到一个 `cm` 矩阵，用 `q cm Do Q` 画上去。原内容会被 pdf-lib 用 `q … Q` 包起来，原内容残留的坐标变换不会影响印章。

测试（`core/test/export.test.ts`）用 pdf-lib 生成 0/90/180/270 度旋转、带 CropBox 偏移、原内容残留变换矩阵的页面，盖章后再用 pdf.js（和界面预览是同一个库）读回操作符列表，计算图片在显示坐标里的实际位置，误差小于 0.01 pt。

**100% 缩放 = 真实尺寸**：1 pt 显示为 96/72 个 CSS 像素，和 pdf.js 官方查看器一致。

## 4. 数据模型

```ts
SealAsset   { id, name, kind: 'seal' | 'signature', widthMm, heightMm, png, pixelWidth, pixelHeight, origin }
Placement   { id, sealId, pageIndex, cxMm, cyMm, widthMm, heightMm, rotationDeg }   // 中心点 + 尺寸
StraddleOptions { enabled, sealId, side, fromPage, toPage, oddPagesOnly, skipFirstPage, centerYRatio, widthMm, maxPagesPerSeal }
```

印章统一保存为透明底 PNG，物理尺寸单独记录。第二阶段的印章设计器会额外保存矢量 SVG 源稿（文字转成路径，不依赖本机字体）。

## 5. 骑缝章

1. `straddlePages` 按页码范围、跳过首页、只盖奇数页算出参与的页。
2. `splitGroups` 在页数太多时分组：每组不超过「每枚最多」页数，每组至少 2 页，尽量平均。
3. `planStraddle` 给每页分配切片：纸张叠放时第 1 页在最上面。盖右侧骑缝章时后面的页依次向右错开，所以第 1 页拿印章最左边的一条；左侧相反。
4. 导出时把印章图片**按像素真正切开**，每页只嵌入自己那一条。如果用裁剪路径遮住，每页仍包含完整印章图片，可以被直接提取出来。

## 6. 导出与已知限制

- pdf-lib 会重新保存整个文件（不是增量保存），所以**原有的数字签名会失效**。打开文档时会检测并提示。第四阶段做 PAdES 签名时会改为增量写入（Rust 实现或改用支持增量保存的库）。
- **加密文档**（有权限密码）暂时只能预览不能导出；需要打开密码的文档暂不支持。
- 印章以 PNG 嵌入。矢量印章（SVG 直接转 PDF 路径）放在第二阶段。

## 7. 平台差异

| 能力 | 网页版 | 桌面版 |
| --- | --- | --- |
| 打开 / 保存 | `<input type=file>`；保存时 Chrome / Edge 用文件选择器，其他浏览器下载 | 系统对话框 + 读写用户选中的文件（Tauri dialog / fs 插件，权限只覆盖用户选中的路径） |
| 印章库 | IndexedDB | IndexedDB（WebView 数据目录）；第四阶段改为加密文件 + PIN |
| 扫码手写签名 | 不支持（浏览器不能监听端口），用鼠标 / 触屏签或导入照片 | 内置局域网 HTTP 服务 |
| Word 导入 | 不支持，提示先转 PDF | 调用 Word / LibreOffice |
| 数字签名 | 导入 .pfx 证书文件 | 系统证书、UKey |

## 8. 后续阶段的技术方案

### 扫码手写签名（第二阶段，桌面版）

- Rust 端（axum 或 tiny_http）在随机端口启动 HTTP 服务，只提供一个单文件手写页面和一个上传接口。
- 列出所有网卡地址，默认选择和默认网关同网段的地址，允许用户切换；二维码旁同时显示网址。
- 二维码带一次性随机 token：5 分钟过期，上传一次即作废，签完自动关闭服务。
- 连不上时给出明确提示（访客 Wi-Fi 的 AP 隔离、系统防火墙），并提供鼠标签名和导入照片两条备用路径。
- 手写页面用 Pointer Events 采集笔画和压感，perfect-freehand 平滑；同时上传 SVG 笔迹和裁掉空白的透明 PNG。

### 印章设计器（第二阶段）

- 预设模板：公章 / 合同专用章（圆形 38–42 mm，五角星）、财务专用章、发票专用章（椭圆 40×30 mm，税号）、法人章 / 名章（方形）。用户主要修改文字、编码和尺寸，高级选项再开放形状和颜色。
- 文字用 opentype.js 转成路径后保存，换电脑不变样。只随包附带 OFL 等开源授权字体（思源宋体、思源黑体），用户可以导入自己的字体但不随包分发。
- 仿真做旧不写进 SVG 原稿，导出时用随机种子叠加。

### 数字签名（第四阶段）

- PAdES-B 签名 + DocMDP 文档锁定，增量保存。先支持自签证书和 .pfx，之后对接 CFCA 等 CA 和 UKey（PKCS#11）。
- 用章日志：时间、文档名、文档 SHA-256。
